The arXiv paper builds serving-engine cost models for latency, throughput and memory into differentiable architecture search. Engineering & Tooling

★ LEAD Primary (Anthropic post, fetched) + TLDR Dev; September baseline corroborated by TechRadar. Vendor's own experiment.

1,000 Fable 5.2 agents reproduced a formal Fermat's Last Theorem proof in 28.7 hours, coordinating only through Git and Postgres

Anthropic's team ran one lead and 999 helpers, each in its own VM with no network except a gateway pipe, plus per-agent Git branches and a shared Postgres database for claims, notes and logs. The September effort needed 11 days; this run used about one-third the output tokens and produced a proof one-seventh the length. The authors call it a toy experiment, and cost was not reported.

Why it matters: Coordination, isolation and monitoring, not the model alone, are what let agent count scale; copy the claim-a-subtask table and the fail-closed command monitor.

Primary (guide, fetched) + TLDR Dev. Author's numbers, not independently reproduced.

Osmani's model-selection guide: raise effort before changing model; low-then-retry hit about 97% at $0.17 per task

The guide recommends starting on Opus 5.5 at medium effort and escalating through self-verification, one effort level, then a bigger model. In its SWE-bench-style example, Opus 5.5 at low with failures retried at high passed about 97% of tasks at roughly $0.17 each, against 95.3% at $0.29 for high on everything. It also warns that prompt caches belong to one model, and Fable 5.2 thinking blocks must stay append-only or the API returns a 400.

Why it matters: A concrete escalation order and cache and thinking-block gotchas you can encode in your router today.

Primary (PostHog newsletter, fetched) + TLDR Dev. Vendor-supplied cost claims noted.

PostHog: decision models skip 98.7% of LLM calls in a PII gate

PostHog uses small models that return a typed answer and a calibrated probability before calling a large model. Two narrow yes/no checks gate its session-summary rewrite, with a low 0.4 threshold because a missed leak costs more than an extra call. Authors note thresholds do not transfer across tasks or model versions, and vendor cost claims are not independently measured.

Why it matters: Gate expensive calls with calibrated narrow classifiers, and set thresholds by the cost of each error type.
