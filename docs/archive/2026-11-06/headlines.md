## ★ Lead
1. **★ LEAD — Anthropic message threads: ~35% lower median time to first token at 500k–1M tokens, same token usage** — Public beta (Nov 2) in the Messages API. The first request sends the full conversation and starts a thread; later requests send only new messages plus the previous response ID. Threads live in encrypted memory and expire 5 minutes after the last request, so the client must keep its own history and replay it. Claude still reads everything each turn, so tokens and rates are unchanged. The 35% is Anthropic's median for Claude Code users, where threads are on by default. Sources: [Anthropic resource (primary)](https://claude.com/resources/articles/message-threads) · [Anthropic blog (primary)](https://claude.com/blog/message-threads) · [Unite.AI (derivative; no independent testing)](https://www.unite.ai/anthropic-launches-message-threads-beta-for-long-running-agents) · [TLDR Dev](https://tldr.tech/dev). *[Primary + 2 secondary (vendor-sourced)]* *Why it matters: Latency in long agent loops is a request-shape problem, not a model problem. Build a replay path before relying on threads; the gain scales with context size.*

## Engineering & Tooling
6. **Agentic technical debt: put approvals, retries and audit in the orchestration layer, not the prompt** — Kai Waehner splits an agent stack into model, harness, durable execution and a control plane. Approvals, compensation and cross-system audit belong to the control plane; retries of side-effecting steps should be keyed on business IDs and kept out of the agent loop. For a single agent inside one app, he says a control plane is unnecessary. His example uses Kestra, so it is partly a vendor-adjacent view. Sources: [Kai Waehner blog](https://www.kai-waehner.de/blog/2026/11/03/agentic-technical-debt-and-where-orchestration-belongs-in-ai-agent-architecture/) · [TLDR Dev](https://tldr.tech/dev). *[Primary (single author)]* *Why it matters: A clean ownership checklist for the system around the model.*

7. **Microsoft Clarity trims clarity.js by 1,257 gzip bytes (4.5%) with an agent running 50+ measure-and-revert experiments** — Named imports saved 444 bytes and Terser tuning 301. Sources: [Microsoft Clarity blog (primary)](https://clarity.microsoft.com/blog/how-we-made-clarity-js-smaller/). *[Primary]* *Why it matters: A concrete example of an agent in a build-measure-keep loop; the metric (compressed size) did the steering.*
